## Learned User Preferences

- Target Flutter Windows desktop (`flutter run -d windows`) from `c:\i\zenda` for dev; build Android release via `flutter build apk --release`.
- When Firestore has no matching record for a demo flow (e.g., parent `STD001`), synthesize an in-memory fallback (e.g., `_buildDemoStudent`) so the UI is explorable end-to-end.
- New UI must read colors from `Theme.of(context).colorScheme.*` tokens via the shared `lib/theme/` system — avoid hardcoded hex like `0xFF1A5F5F` and honor the teal ↔ orange + light/dark switch.
- Before committing Dart, audit for stray `Â·` (U+00C2 U+00B7) that should be middle-dot `·` (e.g. `rg "Â" --type dart`); it recurs in admin list subtitles.
- Demo credential rows on the login screen should be tappable and auto-fill email/password — role is auto-detected from the identifier (no manual role picker); the form also persists the last-used identifier separately from the auth session via a "Remember this user" checkbox so it survives logout (`AuthStorageService.{save,get,clear}LastLoginIdentifier` against the `auth_last_login_identifier` SharedPreferences key).
- Modal dialogs that run background work (e.g., fingerprint scan) must include a Cancel button that cancels timers/subscriptions and resets `_isScanning` without raising an error.
- When fixing Flutter sliver/`ListView.builder` assertions, add stable `ValueKey`s, cancel any `StreamSubscription` in `dispose`, and guard `setState` with `if (!mounted) return;`. Never put `Spacer()` inside `AlertDialog.actions` — the actions slot uses `OverflowBar` (not a `Flex`), so a misplaced `Spacer` collapses the whole dialog body to a blank grey panel; instead use `actionsAlignment: MainAxisAlignment.end`, push left-anchored buttons (e.g. Delete) into the `title` `Row` with `Expanded`, and bound dialog bodies with `ConstrainedBox(maxWidth: …)` + `SingleChildScrollView`.
- Place new admin CRUD screens under `lib/screens/admin/` and shared admin widgets under `lib/widgets/admin/` (reuse `admin_list_scaffold.dart`).
- New Firestore-backed models should follow `lib/models/school.dart`'s `fromFirestore` / `toFirestore` + `_parseDate` pattern.
- Logout pattern: `AuthService.signOut()` (clears the Firestore-backed in-memory session + `AuthStorageService.clearStoredLogin()`) then `Navigator.pushNamedAndRemoveUntil(context, '/login', (_) => false)`.
- Workforce-wide features must cover all user kinds, not just workers — time-off covers teachers/admins/staff/workers; custom-role assignments live as a `roleId` FK on workers/teachers/admins (not a free-form `role` string); role pickers must show every active school role and must NOT re-filter by `Role.appliesTo` (it is a soft default-audience hint, not a hard filter — any role can be assigned to any kind) nor double-gate on strict `schoolId` equality (`getRoles()` already scopes via `_scoped`, and legacy role docs may carry empty/mismatched `schoolId`); init guards in `teachers_screen`/`admins_screen`/`workers_screen` should clear `selectedRoleId` only when the role is no longer in `_roles`, never based on `appliesTo`; the school-admin sidebar drops the generic `Workers` bucket in favor of one row per custom role plus a synthetic `Unassigned` row counting people with `roleId == null`; uploaded supporting documents (e.g., time-off attachments) go inline in Firestore as Base64 (`attachmentBase64` + `attachmentContentType`, optional `attachmentFileName`) — use `image_picker` (works on Flutter Web) over `file_picker` (throws `LateInitializationError` on web), and stay under the 1 MiB Firestore doc cap.
- When asked to "copy [a built artifact] to clipboard" (e.g. the release APK), put the actual file on the clipboard via a FileDropList so Ctrl+V pastes the file in Explorer — not the path string.

## Learned Workspace Facts

- Project is a Flutter 3.7 + Firebase school attendance app named `zenda`, rooted at `c:\i\zenda`.
- Four user roles (enum `UserRole`: `systemOwner`, `schoolAdmin`, `teacher`, `parent`); role strings on `users/{uid}.role` are `system_owner`, `admin`/`school_admin`, `teacher`, `parent`. `lib/services/auth_service.dart` is the single Firestore-only login entry point (`signInWithEmail`, `signInAsParent`, `restoreSession`, `signOut`); `auth_storage_service.dart` caches the `AuthSession` in SharedPreferences and `AuthWrapper` in `lib/main.dart` re-reads `users/{uid}` on restore. `lib/screens/login_screen.dart` has no manual role picker — email identifiers go through `signInWithEmail` + Firestore role lookup, student-number identifiers through `signInAsParent`.
- Demo logins (work against empty Firestore via `AuthService`'s synthetic fallback): `owner@school.com / owner123`, `admin@school.com / admin123`, `teacher@school.com / teacher123`, parent `STD001 / parent123`.
- `lib/services/firebase_service.dart` owns all Firestore I/O; `_scoped()` auto-applies a `schoolId` filter for non-owner callers across `students`/`devices`/`users`/`teachers`/`classes`/`parents`/`workers`/`roles`/`worker_time_off`/`device_enrollments`. Admin sections live under `lib/screens/admin/` (each uses `lib/widgets/admin/admin_list_scaffold.dart`); system owner dashboard exposes Dashboard, Schools, Devices, Teachers, Classes, Parents, Sessions, Workers, Time off, Custom roles, System. Collection inventory is tracked in `FIRESTORE_COLLECTIONS_ANALYSIS.md`. Device fingerprint enrollment (`lib/screens/admin/device_enrollments_screen.dart`) supports up to 200 slots and allocates incrementally; Firestore `device_enrollments/{deviceId}_{slotId}` (deterministic doc id, model in `lib/models/device_enrollment.dart` that round-trips Flutter names `name`/`phone`/`slotId` and legacy api-v2 names `userName`/`userPhone`/`userId`) is the single source of truth. `FirebaseService.{getDeviceEnrollments,upsertDeviceEnrollment,deleteDeviceEnrollment,clearDeviceEnrollments}` go through `_scoped`; `DeviceEnrollmentLookup.fetch` does one school-wide Firestore query (no per-device HTTP fanout). Dashboard `_loadData()` methods use `Future.wait` to load in parallel — non-critical optional reads (e.g. `getRecentActivity` over `api_logs`) must route through `_getWithAuthRetry` and silently return `[]` on `permission-denied`, otherwise a single failing optional query rejects the whole `Future.wait` and discards the schools/devices that already loaded. The api-v2 server still publishes MQTT enroll/delete/clear commands but is no longer the system of record — Render's free tier sleeps after ~15 min and `broker.hivemq.com` is QoS 0 (no offline queue), so MQTT acks were unreliable; `_EnrollDialog._submit()` posts the MQTT command, polls for confirmation, then writes Firestore before closing (no more `_pendingEnrollments`/`_refreshFromDevice` round-trip).
- Unified theme system lives in `lib/theme/` (`app_colors.dart`, `app_theme.dart`, `theme_controller.dart`); `ThemeController` persists `ThemeMode` + `AppPrimary` (teal/orange) via SharedPreferences keys `pref.theme_mode` / `pref.theme_primary` and exposes `ThemeSwitcher` for AppBars. `system_owner_dashboard.dart` is wrapped in a scoped `Theme(data: AppTheme.light(primary: …))` and is light-only by design.
- Morning/Afternoon is gone: `Student.sessionIds: List<String>` references `sessions/{id}`; `Session` is a configurable attendance window with `name`, `date`/`endDate`, `recurrence` (`none`/`daily`/`weekly`/`monthly`/`yearly`), `lateTime`, `classIds`/`classNames`, `audienceRoles: List<String>` (any built-in or custom role key), and `attendees: List<SessionAttendee>` (per-person picks; `SessionAttendee.kind` ∈ `teacher`/`admin`/`staff`/`worker` + `roleKey`); `lib/models/session_attendee.dart` is the attendee model. Sessions also support per-day calendar overrides via `SessionDateOverride` (`date`, `excluded`, optional `startTime`/`endTime`/`lateTime`) with helpers like `overrideFor`, `isSkipped`, and `effectiveTimesFor`; recurring sessions let admins customize future occurrences from the calendar instead of relying on text inputs. Legacy single-target docs migrate transparently in `Session.fromFirestore`; legacy period data is migrated via System Owner dashboard → Quick Actions → **Migrate period data** (`FirebaseService.migrateSchoolPeriodsToSessions`).
- `firestore.rules` is intentionally open for the Firestore-only auth model because requests do not carry a server-verifiable identity; role + school scoping happens in `FirebaseService` using `AuthService.currentSession`. `storage.rules` allows constrained attachment uploads without auth identity; attachments are uploaded from `widgets/chat/message_input.dart` via `image_picker`.
- Cloud Functions (Node 20) live at `functions/src/index.ts` but currently only initialize Admin SDK; no identity/role-claim functions are needed for the Firestore-only auth model. Build + deploy functions with `npm --prefix functions run build && firebase deploy --only functions` (requires Blaze for deploy).
- Dev environment (Windows): use PowerShell with `;` (not `&&`) and `Set-Location`. Android release needs `-Djava.net.preferIPv4Stack=true` in `android/gradle.properties` (Gradle JVM IPv6 issues to `storage.googleapis.com`); Kotlin Android plugin is pinned to `2.1.0` in `android/settings.gradle.kts`; release APK at `build/app/outputs/flutter-apk/app-release.apk`. Android emulator on this Intel host is unstable with the default `hw.gpu.mode=auto` (host Vulkan) and snapshot fast-boot — they cause repeated `System UI isn't responding` ANRs; cold-boot via `emulator -avd <name> -no-snapshot-load -no-snapshot-save -gpu angle_indirect` and persist the fix in `~/.android/avd/<AVD>.avd/config.ini` (`fastboot.forceColdBoot=yes`, `firstboot.bootFromLocalSnapshot=no`, `hw.gpu.mode=angle_indirect`, `hw.ramSize=2048M`); after boot, mute animations via `adb shell settings put global {window,transition,animator}_animation_scale 0`. Windows desktop: Firebase C++ SDK zip (`build\windows\x64\firebase_cpp_sdk_windows_*.zip`) may truncate via CMake's bundled curl — pre-cache with `Start-BitsTransfer` from `https://dl.google.com/firebase/sdk/cpp/`; reconfigure with `-DCMAKE_INSTALL_PREFIX=C:/i/zenda/build/windows/x64/runner/Debug` since the default `C:/Program Files/zenda` is admin-only.
- School admin desktop shell in `lib/screens/school_admin_dashboard.dart`: outer `Row` should use `crossAxisAlignment: CrossAxisAlignment.stretch` so the main pane fills height. Short scroll pages (Dashboard, Devices): `LayoutBuilder` + `ConstrainedBox(minHeight: viewport maxHeight when finite)` + top-aligned `Column`. A nested `Row` with `CrossAxisAlignment.stretch` inside `SingleChildScrollView` gets unbounded height — wrap with `IntrinsicHeight` only if children are intrinsically measurable; if a child uses a `LayoutBuilder` that breaks the intrinsic-height path (e.g. `_DeviceStatusCard`), swap the row for a `Table` with `FlexColumnWidth(3)/FlexColumnWidth(5)` + `TableCellVerticalAlignment.top` instead. Avoid `IntrinsicHeight` around shrink-wrapped `ListView` (prefer `Column` or explicit height); cards in scroll views must gate `Spacer` on bounded height (e.g. `LayoutBuilder`) to avoid unbounded flex errors.
- Custom roles + staff time-off are school-scoped admin features: `lib/models/role.dart` carries `appliesTo: List<String>` (default `['worker']`, may include `worker`/`teacher`/`admin`/`staff`); `Worker`/`Teacher`/`AppUser` reference roles via a `roleId` FK to `roles/{id}` (legacy free-form `Worker.role` string is read for backward compat then cleared by `FirebaseService.migrateRoleStringsToRoleIds` — surfaced as a System Owner Quick Action). Use `FirebaseService.setPersonsRole({kind, ids, roleId})` and `getRolesByApplyTo(kind, schoolId)`; auth-role string literals are centralized in `lib/services/role_constants.dart` (`AuthRoles.systemOwner`/`admin`/`schoolAdmin`/`teacher`/`staff`/`parent` + `isSchoolAdmin`/`isAdminLike`). `RoleEmployeesScreen` loads workers + teachers + users, groups Add Employee picker by kind, Move dialog includes an `Unassigned` option. `lib/models/staff_time_off.dart` with `assigneeKind` (`teacher`/`admin`/`staff`/`worker`) is stored in `worker_time_off/{id}` (kept for backward compat — legacy worker-only docs default to `worker`); attachments are inline Base64 (`attachmentBase64`/`attachmentContentType`), legacy `attachmentStoragePath`+`attachmentUrl` retained read-only.
- Vercel + GitHub deploy: `origin` is `https://github.com/leoenovate/zenda.git`; Flutter web is built with `flutter build web --release` (~31.6 MB → `build/web/`) and shipped via `vercel deploy --prod --yes` on the `leo-1779` account / `leo-enovates-projects` team (apex `enovate.rw` lives on the same team — there is no separate `leoenovate` account). Each prod deploy needs both aliases repointed: `vercel alias set <deployment-url> zenda.enovate.rw` AND `vercel alias set <deployment-url> zenda-mu.vercel.app` (the project's auto-assigned vercel domain) — the live URL is then copied to clipboard for the user (`vercel domains add` errors on CLI v50.25). `vercel.json` SPA rewrite must use `"/((?!.*\\.).*)" → "/index.html"` (negative-lookahead for paths with a dot) — the naive `/(.*)` intercepts asset requests like `/assets/assets/data.json` and returns HTML, breaking Flutter Web with a JSON `FormatException`. `.vercelignore` needs explicit per-folder excludes inside `build/` (e.g. `build/.cxx/`, `build/app/`, `build/cloud_firestore/`, `build/firebase_*`, `build/flutter_assets/`, `build/windows/`) — `build/* + !build/web` does NOT recursively re-include nested files, and unanchored patterns like `assets/` accidentally match `build/web/assets/`. Set `Cache-Control: no-cache, no-store, must-revalidate` on `/index.html` and `/flutter_service_worker.js`; bumping the SW version (e.g. 805056441 → 396079570) requires `flutter clean` + `flutter pub get` + `flutter build web --release` (the same clean also fixes stale Dart incremental-compile errors that flag valid methods as missing).
